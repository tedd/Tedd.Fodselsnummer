## 2026-06-22 - Regex and LINQ Allocation Optimization in FodselsnummerValidator
**Observation:** `FodselsnummerValidator.Validate(string)` incurred heavy allocations (~2.4 KB) and latency (~2.7 µs) due to its use of `Regex.Match`, `int.Parse(match.Groups)`, `string.Substring()`, LINQ enumerations `Where(...).ToList()`, and parsing variables via arrays `number.Select(...).ToArray()`. This string manipulation and enumerator overhead caused completely unnecessary GC pressure.
**Strategic Action:** Decomposed parsing mathematically. Implemented explicit character arithmetic (`number[0] - '0'`) coupled with numeric composition operators. Replaced LINQ queries with a structural `foreach` array iteration and handled date instantiation structurally avoiding string conversions (`new DateTime(year, month, day)` vs parsing ISO 8601 representation strings). Reduced complexity to O(1) Time and O(1) Space with allocations dropping from 2456 B to 72 B and latency decreasing ~97%.
## 2026-10-31 - Allocation and Latency Optimization in FodselsnummerValidator.Validate(long)
**Observation:** `FodselsnummerValidator.Validate(long)` incurred heavy allocations (~2.5 KB) and latency (~2.8 µs) due to its use of `number.ToString(CultureInfo.InvariantCulture)` mapping into the already slow legacy string validation path which performed `Regex.Match`, `int.Parse`, and string manipulation operations. Passing primitive `long` types resulted in completely unnecessary garbage collector pressure.
**Strategic Action:** Decomposed parsing mathematically using explicit modulo and division arithmetic (`number % 10`, `number / 10`) to extract digit representations securely without strings, and implemented `ValidateInternal` for shared logic processing across both signature paths. Reduced string `Parse` and implicit formatting arrays. Complexity remains O(1) Time and O(1) Space with allocations dropping from 2504 B to 72 B and latency decreasing ~98% (2,854 ns to 49 ns).
